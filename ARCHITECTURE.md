# Архитектура проекта JudgeHelper

Этот проект написан на Python (сервер) и JavaScript (интерфейс). Если вы привыкли к n8n (где всё состоит из блоков/нод), то здесь логика такая же, просто она описана чистым кодом.

---

## Аналогия с n8n

В n8n у вас есть **Webhook-нода** (которая принимает запросы), **ноды обработки**, **нода отправки в AI-сервисы**, и **нода выгрузки файла**.

В нашем коде всё то же самое:
1. **Webhook / Триггер** — функции с декораторами `@app.post(...)` в `backend/main.py`. Они «слушают» запросы от браузера.
2. **Авторизация & Сессии** — `backend/auth.py` проверяет HMAC-подписанные сессионные cookie с версией сессии, а `UserStore` хранит аккаунты и PBKDF2-хеши паролей. Каждая задача доступна только владельцу.
3. **Хранилище состояний** — `backend/db.py` (SQLite WAL) хранит данные пользователей и очередь задач, а также автоматически чистит неиспользуемые блокировки (`remove_lock`).
4. **AI-движок** — `backend/services/ai_service.py` связывается с AssemblyAI и OpenRouter с поддержкой сетевой устойчивости (`async_retry`) и самовосстановления (`recover_pending_jobs`).
5. **Генерация документов** — `backend/services/docx_generator.py` создаёт файлы `.docx` по судебному стандарту.

---

## Структура папок

### 1. `backend/` (Сервер / "Под капотом")
Это сердце приложения, работающее в изолированном Docker-контейнере.
- `main.py` — веб-маршруты FastAPI, обработчик потоковой загрузки и инициализация приложения (lifespan).
- `auth.py` — проверка cookie-сессий (HMAC) и логика входа/выхода.
- `cli.py` — утилита командной строки для CRUD-операций с аккаунтами пользователей (добавление, смена пароля).
- `config.py` — загрузка переменных окружения (`.env`), настроек, динамическое перечитывание промпта (hot-reload) и ротация логов (`RotatingFileHandler`).
- `db.py` — SQLite хранилище для задач (`JobStore`) с индексированными колонками и менеджером блокировок, и хранилище пользователей (`UserStore`).
- `services/` — специализированные модули:
  - `ai_service.py` — фасад обратной совместимости (реэкспорт всех сервисов).
  - `http_client.py` — управление HTTP-клиентом `httpx.AsyncClient` и механизм повторов (`async_retry`).
  - `transcription.py` — интеграция с AssemblyAI (стриминг, word boost) и фоновый поллинг (`aai_polling_loop`).
  - `llm.py` — чанкинг стенограмм с сохранением контекста ролей и каскадный fallback для OpenRouter.
  - `pipeline.py` — оркестрация обработки (`process_transcript`) и самовосстановление (`recover_pending_jobs`).
  - `docx_generator.py` — сборка документов Word с соблюдением судебных отступов и шрифтов.
  - `text_cleaner.py` — движок Regex-замен судебной терминологии и фамилий.
- `tests/` — комплексный пакет автоматических интеграционных и модульных тестов (`pytest`).

### 2. `backend/static/` (Фронтенд / "Внешний вид")
То, что загружается в браузере:
- `index.html` — разметка интерфейса и диалогов.
- `login.html` — шаблон страницы входа в теме Noctalia Monochrome.
- `style.css` — монохромная тема Noctalia.
- `app.js` — логика интерфейса (Drag-and-Drop, таймер ETA, polling статуса каждые 5 сек).

### 3. `prompts/` (Промпты для ИИ)
- `system-protocol.md` — файл инструкций для нейросети. Редактируется на лету без перезагрузки сервера.

### 4. `Caddy` (Сетевой шлюз)
- Работает в отдельном Docker-контейнере, перенаправляет трафик и **автоматически выписывает бесплатный HTTPS-сертификат** (Let's Encrypt).

## Как проходит полный цикл работы (Flow)

1. **Браузер (`app.js`)**: Пользователь перетаскивает аудиофайл в окно браузера. Скрипт отправляет файл на сервер.
2. **Сервер (`main.py`)**: Валидирует заголовки, **потоково (без загрузки в RAM)** сохраняет аудиофайл на диск, создаёт запись в SQLite (`db.py`) со статусом `processing`, и моментально отдаёт `job_id` обратно браузеру.
3. **Фоновый Worker (`ai_service.py`)**:
   - Асинхронно потоково отправляет файл с диска в **AssemblyAI** (`submit_to_assemblyai`) с механизмом `async_retry`, после чего файл удаляется.
   - Ожидает результат через **Webhook** или гибридный фоновый цикл опроса (`aai_polling_loop`).
   - Получает расшифровку (с автоматическим определением спикеров).
   - Очищает текст от ошибок ASR через `text_cleaner.py`.
   - Если текст длинный, разбивает его на чанки и передаёт в **OpenRouter (GPT-4o-mini)**. При этом сохраняется "окно памяти" (контекст из конца предыдущего чанка) для удержания ролей спикеров.
   - Записывает готовый черновик в SQLite, не сохраняя сырую стенограмму, и освобождает блокировку памяти (`remove_lock`).
4. **Браузер (`app.js`)**: Опрашивает статус задачи раз в 5 секунд. При получении статуса `done` отображает метаданные готового протокола и предоставляет кнопку для быстрой генерации и скачивания документа `.docx` (`/render-docx`).
