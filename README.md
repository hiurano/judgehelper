# JudgeHelper

Веб-сервис автоматического распознавания устной речи и генерации официальных судебных протоколов по стандарту Нижневартовского городского суда ХМАО-Югры.

---

## Назначение

Приложение принимает аудио- и видеозаписи судебных заседаний, выполняет распознавание речи (ASR) с разделением спикеров, обрабатывает полученный текст с помощью языковой модели (LLM) и формирует готовый к печати документ формата `.docx`, строго соответствующий правилам судебного делопроизводства.

---

## Ключевые возможности

- **Распознавание речи (ASR):** Расшифровка аудиозаписей через сервис AssemblyAI (модель `universal-2`) с разделением по спикерам и выделением юридических терминов (`word_boost`).
- **Оптимизация текста до LLM:** Высокоскоростной предкомпилированный Regex-движок для автоматического исправления ошибок распознавания ASR (фамилии, статьи УК/УПК РФ, топонимы).
- **Юридическая обработка речи:** Преобразование устной речи в официальный процессуальный стиль на основе настраиваемого системного промпта (`prompts/system-protocol.md`).
- **Очередь и пакетная загрузка:** Поддержка последовательной обработки нескольких файлов с визуальным отслеживанием прогресса и расчётом оставшегося времени (ETA).
- **Отказоустойчивость LLM:** Каскадная цепочка резервных моделей (DeepSeek / Gemini / OpenAI) с автоматическим переключением при сбоях основной модели.
- **Форматирование по судебному стандарту:** Автоматическое построение документов Word (Times New Roman 12pt, красные строки 1.25 см, поля, табуляция подписей и дат по правому краю 16.5 см).
- **Авторизация и безопасность:** Встроенная cookie-авторизация на базе HMAC-токенов с подписью.
- **Надёжное хранение:** Хранение очереди задач и результатов в SQLite в режиме WAL с автоматической очисткой устаревших записей (`JOB_TTL_DAYS`).
- **Высокая производительность:** HTTP Connection Pooling (Keep-Alive), сетевое GZip-сжатие ответов и целевое DOM-обновление таймеров на фронтенде без лишней нагрузки на CPU/аккумулятор.

## Технологический стек

- **Backend:** Python 3.11+, FastAPI, Uvicorn, SQLite3, `httpx`, `python-docx`
- **AI Services:** AssemblyAI (Speech-to-Text), OpenRouter (LLM DeepSeek / Gemini / OpenAI)
- **Frontend:** HTML5, CSS3 (Everforest Dark Medium), Vanilla JavaScript, PWA
- **Инфраструктура:** Docker, Docker Compose, Ngrok

## Переменные окружения (.env)

Для конфигурации приложения создайте файл `.env` в корневом каталоге проекта:

```env
# API Ключи
ASSEMBLYAI_API_KEY=your_assemblyai_key
OPENROUTER_API_KEY=your_openrouter_key

# Настройки LLM
LLM_MODEL=deepseek/deepseek-v4-flash-0731

# Сетевые настройки и вебхуки
BASE_URL=https://your-domain.com
WEBHOOK_SECRET=your_webhook_secret
ALLOWED_ORIGINS=*

# Авторизация (необязательно)
AUTH_USERNAME=admin
AUTH_PASSWORD=your_secure_password

# Настройки базы данных и хранения
JOB_TTL_DAYS=30

# Ngrok Токен
NGROK_AUTHTOKEN=your_ngrok_token
```

## Быстрый запуск (Docker Compose)

Приложение полностью контейнеризировано и запускается **одной командой**:

1. Создайте и заполните файл `.env` (на основе примера `.env.example`).
2. Запустите сервис:
   ```bash
   docker compose up -d --build
   ```

### Управление сервисом:
- **Просмотр логов:** `docker compose logs -f`
- **Остановка:** `docker compose down`

После запуска сервис автоматически доступен:
- Локально: **`http://localhost:8000`**
- Удалённо (для мамы): по вашей постоянной ссылке Ngrok из `.env`.

## Требования к оформлению документов (.docx)

Сгенерированные протоколы формируются согласно следующим параметрам судебного делопроизводства:

- **Шрифт:** Times New Roman, 12 pt
- **Межстрочный интервал:** 1.0 (одинарный), отступы до/после — 0 pt
- **Красная строка:** 1.25 см
- **Поля страницы:** Левое — 3.0 см, Правое — 1.5 см, Верхнее — 2.0 см, Нижнее — 2.0 см
- **Выравнивание:** По ширине (для заголовков — по центру)
- **Табуляция:** Выравнивание подписей и дат по правому краю на 16.5 см
